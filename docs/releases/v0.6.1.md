# Selo v0.6.1

Patch release. One bug fixed; nothing else changed.

## What changed

`ParseTaskConfig` (the function that reads a task file) tracked its YAML-ish
sections with sticky flags. A `forbidden_files:` header closed `allowed_files:`
but **not** `commands:`, so every forbidden path was also appended to the list of
test commands and then executed.

The documented task layout puts `commands:` before `forbidden_files:` (see
`docs/spec-v0.1.md`), so the default configuration always hit this. The visible
symptom was a bogus line in the receipt's signed `test_output` field:

```
$ python3 -m pytest -q
1 passed in 0.30s
$ README.md
[error: exec: "README.md": executable file not found in $PATH]
```

`README.md` was only ever passed as a forbidden file.

## Why this warranted a release

The safety scan itself was **not** weakened — the forbidden-file check still held
the right entries and `FAILED_SAFETY` fired correctly. What was wrong is that a
**signed** field recorded commands that were never configured. For a tool whose
whole claim is "the receipt is an honest record of what was observed," a
systematically wrong field is worse than a crash.

## What you get

- `forbidden_files`, `allowed_files`, `forbidden_claims`, `commands` and
  `deliverables` are now fully disjoint; a header closes every other section.
- Three regression tests in `internal/governor/governor_test.go`, each proven to
  fail against the old code with the exact leaked values and to pass after the fix.
- No receipt-schema, config, or CLI changes. Receipts from v0.6.0 verify unchanged.

## Upgrade

Same as v0.6.0: `curl -fsSL https://selo.c1.run/install.sh | sh`, or grab the
binaries / `checksums.txt` / `checksums.txt.sigstore.json` from the release
assets and verify with `install.sh`. The cosign keyless identity is unchanged
(`C1-run/Selo`, because this is `< v0.7.0`).

## Still true (no change in this release)

- Default backend: the signing key is on the same host/OS-user as the agent, so a
  receipt proves what Selo observed, not that the agent couldn't forge it. Use the
  `command` backend (ADR-008) for a key outside that domain.
- RFC3161 timestamping and Rekor transparency-log entries are opt-in flags, not
  defaults.
- `cmd/selo` has three daemon/anchor tests that are flaky under full-suite load
  (`anchor failed: git add: fatal: not a git repository`). Pre-existing and
  unrelated to this fix; tracked separately.

# Selo v0.6.2

Patch release. One reliability fix; **no shipped binary behavior changed**.

## What changed

The `cmd/selo` daemon / c1loop / anchor end-to-end tests were intermittently
failing under full-suite load. v0.6.1's notes flagged this as "tracked separately"
— it is now resolved.

Root cause: every `TestC1Loop*`, `TestDaemon*`, `TestRealRun*` and P45 test shared
**one** global fixture git repo at `/tmp/selo-fixture` and ran
`git worktree add -b selo/<taskID>` with **fixed branch names**
(`selo/c1-noop`, `selo/real-noop`, `selo/c1-fail`, …). `cleanupStaleBranches` only
removes worktree *directories* whose path contains `worktrees`/`wt-`, so
registered-worktree **metadata** left behind by a prior run on the shared repo made
the next test's `git worktree add` fail. The symptom was an intermittent
`FAILED_INTERNAL_ERROR` ~0.25s in, with no `Preparing worktree` log line. A second,
misleading `anchor failed … not a git repository` non-fatal error (from anchoring the
test's *non-repo* queue directory) obscured the real cause during diagnosis.

Fix:
- Each test now creates its **own isolated fixture repo** under `t.TempDir()`, so
  git state — branches, registered worktrees, the receipt-anchor branch — cannot
  leak between tests.
- The best-effort receipt anchor is disabled in the daemon E2E harness
  (`SELO_DISABLE_ANCHOR=1`); it remains covered by
  `internal/receipt/anchor_test.go` against a real repository.

## Why this warranted a release

A CI signal that randomly goes red is worse than no signal: it trains reviewers to
skip the run, which is exactly when a real regression slips through. This patch
makes the daemon test path deterministic so the suite can be trusted again. The
change is confined to `cmd/selo/main_test.go` (test harness only) — the agent
binary, receipt schema, config, and CLI are unchanged.

## What you get

- The full `cmd/selo` suite passes **74/74 three consecutive times** (verified with
  `go test ./cmd/selo/ -count=1 -timeout 0 -v`, repeated 3×, zero failures).
- No receipt-schema, config, or CLI changes. Receipts from v0.6.1 verify unchanged.
- `internal/receipt/anchor_test.go` continues to cover the anchor against a real
  repo, so disabling it in the E2E harness loses no coverage.

## Upgrade

Same as v0.6.1: `curl -fsSL https://selo.c1.run/install.sh | sh`, or grab the
binaries / `checksums.txt` / `checksums.txt.sigstore.json` from the release assets
and verify with `install.sh`. The cosign keyless identity is unchanged
(`C1-run/Selo`, because this is `< v0.7.0`).

## Still true (no change in this release)

- Default backend: the signing key is on the same host/OS-user as the agent, so a
  receipt proves what Selo observed, not that the agent couldn't forge it. Use the
  `command` backend (ADR-008) for a key outside that domain.
- RFC3161 timestamping and Rekor transparency-log entries are opt-in flags, not
  defaults.
- The flaky `cmd/selo` daemon/anchor tests described as "tracked separately" in the
  v0.6.1 notes are **resolved** by this release.

# Selo v0.6.3

Patch release. One reliability fix; **no shipped binary behavior changed**.

## What changed

v0.6.2 made every `TestC1Loop*` / `TestDaemon*` / `TestRealRun*` / P45 test use its
own isolated fixture repo, killing the shared-`/tmp/selo-fixture` worktree-contamination
flake. One test was missed: `TestOpenCodeCannotPassByDeletingTest` (the OpenCode
negative-control, gated behind `SELO_RUN_OPENCODE_E2E=1`) still pointed `processOneTask`
at the shared `/tmp/selo-fixture-opencode` with the fixed branch `selo/opencode-neg-control`.

That test is **skipped in the default suite**, so it could not flake normal CI — but
enabling E2E mode and running under load would have reintroduced the exact same
registered-worktree-metadata contamination (a later `git worktree add` failing with
no `Preparing worktree` log). This release closes that last shared-fixture path: the
test now builds its own isolated repo under `t.TempDir()` via a new parameterized
`ensureOpenCodeFixtureRepoAt`. The `TestRealOpenCodeSoak*` tests already used hermetic
fixtures and were unaffected.

## Why this warranted a release

A latent flake is still a flake — the moment someone enables the E2E path (which is the
path that actually exercises the OpenCode adapter end-to-end), it would have gone red
intermittently and trained the same "skip the run" habit v0.6.2 set out to remove. The
fix is mechanically identical to the already-proven v0.6.2 change, so it inherits that
evidence rather than needing a separate stress run (which could not be executed in the
build sandbox anyway, as the test requires the opencode model API).

## What you get

- All `cmd/selo` daemon/anchor/c1loop/OpenCode E2E fixture repos are now hermetic.
- Default suite unchanged: still **74/74, 0 failures** (the OpenCode test remains
  skipped unless `SELO_RUN_OPENCODE_E2E=1`).
- No receipt-schema, config, or CLI changes. Receipts from v0.6.2 verify unchanged.

## Upgrade

Same as v0.6.2: `curl -fsSL https://selo.c1.run/install.sh | sh`, or grab the
binaries / `checksums.txt` / `checksums.txt.sigstore.json` from the release assets
and verify with `install.sh`. The cosign keyless identity is unchanged
(`C1-run/Selo`, because this is `< v0.7.0`).

## Still true (no change in this release)

- Default backend: the signing key is on the same host/OS-user as the agent, so a
  receipt proves what Selo observed, not that the agent couldn't forge it. Use the
  `command` backend (ADR-008) for a key outside that domain.
- RFC3161 timestamping and Rekor transparency-log entries are opt-in flags, not
  defaults.
